## The week in one paragraph

The week's AI-engineering story is a big US open-weight model. On **15 October**, Meta released **Muse Spark Open**, an open-weight version of its Muse Spark model. Coverage describes it as an **816B-parameter mixture-of-experts model with 42B active parameters and a 1M-token context**. The weights are on Hugging Face and the major clouds, under Meta's own "Muse Model License" rather than an open-source license. For teams that must keep patient data on their own hardware, that is a new near-frontier option to evaluate. Independent scores are mixed, though. On GitHub, **`anthropics/claude-plugins-official`**, Anthropic's managed directory of Claude Code plugins, gained about 4,800 stars, while `morluto/rea` (last week's item) kept climbing. Gemini 4 Argon became broadly available on 13 October, and DeepSeek shipped V4.1-Flash-1017 on 17 October. Neither was read at the source this run (see Also noted).

## So what

*For healthcare data scientists, ML engineers in healthcare, and healthcare executives.*

- **Healthcare data scientists:** **Muse Spark Open** is a large model you can run yourself. That means you could test it on real notes without sending them out. But its scores are mixed: #38 of 49 on one broad test, #3 on a finance task. Don't trust the launch claims. Run it on one task you already score, like coding diagnoses from notes, and compare it to what you use now.
- **ML engineers in healthcare:** Open weights let you keep private health data (the law calls it PHI) inside your own walls. You can also host it in SageMaker, Google Cloud or Microsoft Foundry under contracts you may already have. It is big, though. Even with only 42B parameters active at a time, it needs serious hardware. For **claude-plugins-official**: a vendor-run plugin list is a better starting point than random repos. Still review each plugin before it touches a clinical system.
- **Healthcare executives:** Read the **Muse Model License** before your team builds on it. It is Meta's own license, not open source, and it limits some commercial use. Have legal check the terms against how you'd use it. If they fit, a self-hosted model could cut your risk of sending patient data to an outside AI vendor.

### Problems worth taking on

**Test a self-hosted model on one clinical text task.** *Problem:* Many health systems can't send notes to cloud AI tools, so tasks like chart summaries stay manual. *Why now:* **Muse Spark Open** is a large open-weight model you can host inside your own cloud account. *First step:* Have legal clear the Muse Model License. Then have an ML engineer host it in your existing cloud setup and run it on 100 notes with known answers. A data scientist scores it against your current tool. Success is matching that tool's accuracy with no data leaving your account.
