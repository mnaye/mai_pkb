## Items

- **[NVIDIA/auto-ontology](https://github.com/NVIDIA/auto-ontology)** `topic:context`. GitHub repo, **~11.0k stars, +9,327 this week** (GitHub Trending, weekly view, read 2026-11-09). Apache-2.0. "Auto Ontology is a Python framework for building semantic, graph-based reasoning layers over data."
  - **What it does:** generates an ontology from database metadata, lets people **certify terms and SQL definitions**, and answers natural-language questions by turning them into SQL. It returns the SQL and the steps it used.
  - **How agents use it:** the README says "Agents need a context layer that tells them where data lives," and that it can "serve context to any agent harness through MCP, CLI, and API." It ships an MCP server and agent skills.
  - **Stack:** web app, FastAPI backend, Postgres/pgvector store, with NVIDIA NIM-hosted models for inference by default.
  - **Limits:** "This project is currently not accepting external contributions." No release is published yet, and the README names no healthcare use.

  *Repo page and GitHub Trending (weekly) fetched 2026-11-09. Creation date was not shown, so "new" is inferred from most of its stars arriving this week.*

## So what

*For healthcare data scientists, ML engineers in healthcare, and healthcare executives.*

- **Healthcare data scientists:** **NVIDIA/auto-ontology** turns plain questions into SQL (the code that pulls data from a database). It checks them against terms and definitions your team has approved. It also shows the SQL it wrote, so you can check every answer. Try it on a copy of a small, de-identified table set. Approve one tricky definition, like "readmission," and see if the tool sticks to it.
- **ML engineers in healthcare:** **auto-ontology** builds its map from your database's metadata, and by default it uses AI models hosted by NVIDIA. Check what it sends out. Column names and sample values can leak private health data (the law calls it PHI). Point it at a model you host, or at fake data, before any real test. There is no release yet, and NVIDIA is not taking outside code changes. Treat it as a pattern to study, not a product to deploy.
- **Healthcare executives:** The tool's big idea is a shared, approved list of what your data terms mean. Agents then work from that list. Most health systems already fight over metric definitions. Ask your data lead who owns those definitions today, and whether they are written down where a tool could use them.

### Problems worth taking on

**Write down your top quality-metric definitions as approved SQL.** *Problem:* Teams answer "what is our 30-day readmission rate?" with different numbers, and each answer costs analyst time. *Why now:* **NVIDIA/auto-ontology** shows a way for AI to answer from definitions people have signed off on. *First step:* Have one analyst write approved SQL for five common metrics on a de-identified dataset. Have the quality lead sign off. Success is the tool giving the same answer as the analyst on 20 test questions.
