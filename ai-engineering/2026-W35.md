*Week of 24–30 August 2026. Curated by Mai with Claude.*

## The week in one paragraph

The agent harness became a **plugin platform** this week. DeepSeek's open-source [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) — tagline *"Everything is a Plugin"* — is the loudest example, sitting at **190.2k stars** and MIT-licensed while still labelled a developer preview. The tell that this is a pattern rather than one repo: the meta-framework it is built on, [cordis](https://github.com/cordiverse/cordis), rode into the weekly trending list on its coattails (**+2,725 stars**), and two vendor plugin registries — [anthropics/claude-plugins-community](https://github.com/anthropics/claude-plugins-community) and [cursor/plugins](https://github.com/cursor/plugins) — climbed alongside it. Where last week's momentum was about what an agent *remembers* ([OpenViking](https://github.com/volcengine/OpenViking) is still trending, now **32.7k stars, +3,799**), this week's is about what an agent can be *extended with*, and who owns the registry that extension ships through. Nothing new landed in the productionizing-healthcare-models track inside the 7-day window.

## So what

*For healthcare data scientists, ML engineers in healthcare, and healthcare executives.*

- **Healthcare data scientists:** AI coding tools now take "plugins." These are small add-ons that teach an agent a new task. A task your team repeats, like pulling a standard data set, could become a plugin everyone shares.
- **ML engineers in healthcare:** DeepSeek released its agent tool, **deepseek-harness**, under the MIT license. That license lets you use and change it freely. But it is an early preview, and the makers say it will change. Don't build anything important on it yet. Plugin formats are also splitting by vendor, with Anthropic and Cursor each running their own. If you build tools for agents, keep the main logic apart from any one vendor's format. Then you can switch later.
- **Healthcare executives:** Two of the three big AI coding vendors now run their own plugin stores. Choosing one store could lock you in. Ask your teams to keep internal tools easy to move.

### Problems worth taking on

**One set of data tools that works with any AI agent.** *Problem:* Each team builds its own way for its AI tool to reach data. The same work gets done again and again. *Why now:* Vendors now run plugin stores, and it's still unclear if they will share one format. *First step:* Build one small tool, like looking up a list of diagnosis codes, without tying it to a vendor. Then connect it to two different agents. Write down how much extra work each one took.
