# AI Engineering — 2026-W48

*Week of 23 November 2026 (ISO week 48). Curated by Mai with Claude.*

## The week in one paragraph

A quieter week for releases, and agents kept moving into code review and handoff work. The one item that made the top 3 is **alibaba/open-code-review**, an Apache-2.0 AI code-review CLI that began as Alibaba's internal reviewer. It gained about 3.7k stars in the week of 11–18 November and now has about 55.7k. Its design is the interesting part: fixed, rule-based steps pick the files, group them and match rules, and an LLM agent handles only the judgment calls. That split is easier to audit than a free-running agent. Elsewhere, skill and handoff repos (anthropics/skills, addyosmani/agent-skills) topped GitHub's growth charts.

## Items

- **[alibaba/open-code-review](https://github.com/alibaba/open-code-review)** `topic:agents`. AI code-review CLI, ~55.7k stars (repo page, fetched 2026-11-23), Apache-2.0. **This week:** +3,675 stars from 11 to 18 November, per [Shareuhack's GitHub Trending roundup (18 November)](https://www.shareuhack.com/en/posts/github-trending-weekly-2026-11-18).
  - **Design:** "Open Code Review's core philosophy is to combine deterministic engineering with an agent, each handling what it does best." The fixed pipeline does file selection, review units, rule matching, comment placement and a reflection step. The agent reads full files, searches the codebase and checks other changed files.
  - **Rules:** a built-in multi-language ruleset covering null-pointer errors, thread safety, XSS and SQL injection, with path filtering and custom rules.
  - **Models:** "OpenAI & Anthropic compatible"; "Simply configure a model endpoint to get started," with custom providers. It can also run as a skill or plugin inside Claude Code, Codex, Cursor, Kimi Code and OpenCode, using the host agent's model.
  - **Where it runs:** npm CLI or binaries; GitHub Actions, GitLab CI, GitFlic CI and Gerrit; OpenTelemetry telemetry and a session viewer.
  - **Claim to check:** the README reports higher precision and F1 than Claude Code with the same model on its AACR-Bench (50 repos, 200 PRs), at about 1/9 the tokens, with lower recall by design. This is the project's own benchmark.

  *Repo page fetched 2026-11-23. No release or last-commit date was visible on the page, so recent activity rests on the star growth reported by Shareuhack. Self-hosted model support is implied by custom providers but not stated.*

## So what

*For healthcare data scientists, ML engineers in healthcare, and healthcare executives.*

- **Healthcare data scientists:** Nothing actionable this week. **open-code-review** checks code, not data or models.
- **ML engineers in healthcare:** **open-code-review** uses fixed rule steps for most of the work. An AI agent (a model that takes steps on its own) only makes the judgment calls. That makes its output easier to explain to an auditor than a free-form AI review. It runs in GitHub Actions and GitLab CI. You point it at a model endpoint you pick. Before you run it on code near patient data, confirm where that endpoint sends your code. Then test it on one repo and compare its findings with your current review.
- **Healthcare executives:** **open-code-review** is free under the Apache-2.0 license. It claims better precision than Claude Code at about one-ninth the tokens, but that is the project's own test. Don't buy or drop tools on that claim. Ask your team for a two-week trial with real numbers.

### Problems worth taking on

**Rule-based AI review for code that touches patient data.** *Problem:* Code changes in pipelines that handle patient data need careful review. Reviewers are busy, and misses can become privacy or safety bugs. *Why now:* **open-code-review** pairs fixed rules with an AI agent and plugs into CI. *First step:* Have one ML engineer run it on the last 20 merged pull requests in a data pipeline, using an approved model endpoint. Success is a count of real issues it finds that human review missed, against the false alarms it raises.
