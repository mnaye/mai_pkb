## Items

- **[morluto/rea](https://github.com/morluto/rea)** `topic:skills-tooling`: "Reverse engineer anything with agents, from app behavior down to native binaries." This is one MCP server (plus a `rea` CLI) that gives any agent with local MCP support tools for **native binaries** (via **Hopper, Ghidra or IDA**, returning pseudocode, assembly, symbols and cross-references), **JavaScript/Electron apps, .NET assemblies, websites, Android APKs and devices, firmware, Flutter apps and process behavior**. `npx rea-agents setup` registers it with **Claude Code, Codex, Cursor, Gemini CLI and Grok Build**. Analysis runs locally; static JS and .NET inspection reads files without running them, while runtime capture "runs or interacts with the selected target using your user permissions." The README says the agent's model provider applies its own data policy. **License:** MIT for REA's own code. The README limits use to "lawful research, education, interoperability, software preservation" on software you own or may examine, and it bars cracked commercial tools. **145,797 ★, +126,976 this week; 33.8k forks; 2,528 commits.** *GitHub Trending (weekly) and the repo page were fetched 2026-10-12. The repo page does not show a creation date.*

## So what

*For healthcare data scientists, ML engineers in healthcare, and healthcare executives.*

- **Healthcare data scientists:** Nothing actionable this week. **REA** works on software, not on data. It does not change how you build cohorts or check models.
- **ML engineers in healthcare:** **REA** lets a coding agent take apart compiled programs. Compiled means the code you can't read, like a vendor's app or a device's built-in software (firmware). That can help when an old vendor tool has no docs and you need its data. But the agent sends what it finds to its model provider. If the program holds patient data (the law calls it PHI), that data could leave your walls. Before anyone points REA at a clinical system, check two things. Does your model vendor have a signed HIPAA contract with you? And does the vendor's license allow this kind of analysis?
- **Healthcare executives:** About 127,000 people starred this tool in one week. Attackers can use it too. Your medical devices and desktop apps are now easier to pick apart. Ask your security lead and your device makers how they would respond. Also set a rule now on whether staff may use tools like this on vendor software, before someone tries it.

### Problems worth taking on

**Map an old system's data before you replace it.** *Problem:* Many hospitals run old vendor tools with no docs. Moving their data costs months of guesswork and consultant fees. *Why now:* **REA** lets an agent read how a compiled program stores and sends data. *First step:* Pick one retired or soon-retired tool you own the rights to. Get legal sign-off and use test data only, never real patient data. Have an engineer and the system owner use REA to write down its data formats. Success means that write-up matches what the owner knows, in less than a week.
